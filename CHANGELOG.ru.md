## [v1.6.0] - 2026-06-23

### ✨ Images

- **Каталог облачных образов** — просмотр и скачивание образов ОС из нескольких источников (стандартное зеркало Proxmox и кастомные зеркала); образы загружаются на хранилище Proxmox
- **Автоматическая конвертация в шаблон VM** — опция автоматической конвертации загруженного `.qcow2` образа в шаблон VM Proxmox после завершения скачивания
- **Кастомные зеркала для администраторов** — интерфейс, доступный только администраторам, для добавления, редактирования, просмотра и удаления источников-зеркал для поиска образов
- **Фильтрация образов по архитектуре** — образы фильтруются по архитектуре платформы узла (x86-64, aarch64); дефолт-архитектура соответствует платформе выбранного узла
- **Загрузка образов с прогрессом** — диалог загрузки с отслеживанием прогресса в реальном времени и опциональным переключателем конвертации в шаблон

### 🐛 Исправления

- **Нормализация расширения файла при импорте образа** — расширение `.img` автоматически нормализуется в `.qcow2` при импорте
- **Санитизация имени VM при импорте образа** — имена VM санитизируются при импорте образа для предотвращения ошибок создания; улучшенные сообщения об ошибках для прозрачной обратной связи с пользователем

## [v1.5.2] - 2026-06-20

### 📊 Метрики

- **Реальное время: заполнение дисков VM, IOPS и сетевой I/O** — живые данные по каждому диску, скорости чтения/записи и сетевого ввода/вывода добавлены на вкладку Overview инстанса, в список инстансов и виджет топ-нагруженных на дашборде
  - Backend: `get_vm_fsinfo()` запрашивает данные файловых систем через QEMU guest agent; `metrics_broadcaster` вычисляет скорости I/O (байт/с) из накопленных счётчиков; цикл обновления списка инстансов теперь опрашивает каждую запущенную VM через `status/current` (гранулярность 1 с) вместо `cluster/resources` (10 с от pvestatd), с ограниченным параллелизмом и ритмом 1 с
  - Frontend: карточки по каждому диску, карточки Network I/O и I/O-rate на OverviewTab через WebSocket; колонки Net и Disk I/O в InstancesPage; Disk% отображается только для LXC; метрики в реальном времени на виджете топ-нагруженных на DashboardPage

### ⚙️ Настройки

- **Язык интерфейса для каждого пользователя** — у каждого аккаунта теперь есть собственная колонка `language` (миграция 26); переключатель языка перенесён с вкладки «Панель» на вкладку «Профиль»; язык сохраняется в БД и применяется через `i18n.changeLanguage()` сразу при сохранении

### 🐛 Исправления

- **Поля настроек SMTP/безопасности** — переименованы поля запроса/ответа SMTP (`host`, `port`, `username`, `password`, `from_email`, `tls`); хук настроек безопасности переведён на `/admin/api/security/settings` с типизированным `SecuritySettings`; добавлены i18n-ключи `minutes` / `security_saved`
- **UX формы уведомлений** — добавлены тосты успеха/ошибки для кнопок сохранения SMTP и Telegram; переключатель языка в «Профиле» подключён; поля смены пароля очищаются только при успешном сохранении
- **Telegram — раздел администратора** — убрано поле Chat ID из глобальных настроек Telegram (оно никогда не сохранялось в БД); проверка теперь выполняется через личный раздел «Мои уведомления → Отправить тест»
- **Поле Webhook URL** — убрано нереализованное поле Webhook URL из настроек уведомлений, чтобы не вводить пользователей в заблуждение

## [v1.5.0] - 2026-05-07

### 🐧 LXC — развёртывание из CT-шаблонов

- **Создание LXC из CT-шаблонов** — полный рабочий процесс создания LXC-контейнеров напрямую из CT-файлов Proxmox (`.tar.zst`, `.tar.gz`); выбор узла/хранилища, интеграция с IPAM, поддержка SSH-ключей
- **Единый мастер создания инстансов** — переработанный мастер (`CreateInstanceWizard`) поддерживает как VM-шаблоны (QEMU), так и CT-шаблоны (LXC) в едином многошаговом потоке: выбор типа, браузер шаблонов, конфигурация, подтверждение
- **Переустановка LXC из CT-шаблона** — поддержка переустановки контейнеров, созданных из CT-шаблонов; имя хоста, пароль, SSH-ключи и IP-адрес сохраняются при переустановке
- **Сохранение учётных данных и IP при переустановке LXC** — пароль root, SSH-ключи, IP-конфигурация и шлюз переносятся автоматически при переустановке контейнера
- **nesting=1 по умолчанию** — все новые LXC-контейнеры создаются с включённым `nesting=1` для обеспечения совместимости с systemd 255+ (cgroup v2)
- **Исправлено: двойное URL-кодирование SSH-ключей** — SSH-ключи, передаваемые в API Proxmox при создании LXC, больше не кодируются дважды

### 🔑 Управление SSH-ключами

- **API SSH-ключей** — полный CRUD для библиотеки SSH-ключей пользователя: `GET /api/ssh-keys`, `POST /api/ssh-keys`, `PUT /api/ssh-keys/{id}`, `DELETE /api/ssh-keys/{id}`
- **Управление ключами администратором** — `GET /api/ssh-keys/user/{user_id}` — администраторы могут просматривать и управлять SSH-ключами любого пользователя
- **Отпечаток ключа** — SHA-256 отпечаток вычисляется и сохраняется автоматически при создании/обновлении ключа
- **Хранение приватного ключа** — опциональное зашифрованное хранение приватного ключа рядом с публичным
- **UI управления SSH-ключами** — новая вкладка на странице настроек для добавления, редактирования и удаления SSH-ключей; отображает имя, отпечаток, комментарий и дату создания
- **Выбор ключа в мастере** — при развёртывании VM или LXC можно выбрать SSH-ключи из личной библиотеки; администраторы, создающие инстанс от имени другого пользователя, могут выбирать из ключей этого пользователя
- **Изоляция по пользователю** — обычные пользователи управляют только своими ключами; пользователи с разрешением `users.manage` могут управлять ключами любого аккаунта

### 🗑️ Операции с VM/LXC

- **Автоматическая остановка перед удалением** — если VM или LXC-контейнер запущен в момент запроса удаления, он автоматически останавливается; предотвращает ошибку Proxmox `can't lock file` при уничтожении

### 🖥️ Улучшения фронтенда

- **InstancesPage** — обновлённый макет, улучшенные бейджи статусов и меню действий
- **NodesPage** — обновлённые карточки узлов с более чистым отображением метрик
- **TemplatesPage** — улучшенный список шаблонов с лучшей фильтрацией и управлением группами
- **BackupsPage** — исправлены граничные случаи в списке резервных копий, диалоге восстановления и UI планировщика заданий
- **UsersPage** — улучшенная таблица пользователей с лучшим отображением ролей и индикаторами назначения серверов
- **SettingsPage** — добавлен раздел SSH Keys Manager; общая полировка UX
- **`api-client.ts`** — добавлены методы API SSH-ключей и эндпоинты CT-шаблонов
- **`websocket.ts`** — улучшение стабильности соединения
- **`types/index.ts`** — добавлены типы `SSHKey`, `LXCTemplate`, `LXCDeployRequest`

### 🛠️ Режим разработки

- **Dev mode** — новый оверрайд `compose.dev.yml` для Vite HMR (горячая замена модулей); использовать `pve dev` или `docker compose -f compose.yml -f compose.dev.yml up -d frontend`; исходные файлы монтируются как тома, изменения применяются мгновенно без пересборки
- **Маркер `.dev-mode`** — сигнализирует CLI `pve` о том, что фронтенд запущен в режиме разработки

## [v1.4.0] - 2026-04-06

### 🌐 Сети — управление SDN и интерфейсы узлов

- **Страница сетей** — новая объединённая страница (`/proxmox/networks`) для управления зонами SDN, VNet, подсетями и сетевыми интерфейсами на уровне узла; добавлена в боковую навигацию с специальной иконкой
- **Редактирование зоны SDN** — `PUT /api/servers/{server_id}/sdn/zones/{zone}` — обновление свойств зоны (mtu, dns, reversedns, ipam и т.д.)
- **Редактирование VNet SDN** — `PUT /api/servers/{server_id}/sdn/vnets/{vnet}` — обновление alias, VLAN tag, vlanaware и т.д.
- **Удаление подсети SDN** — `DELETE /api/servers/{server_id}/sdn/vnets/{vnet}/subnets/{subnet_cidr}` — удаление подсети; опционально удаление связанной сети IPAM (`?delete_ipam_network=true`)
- **Автоматическое создание сети IPAM при создании подсети** — `POST .../subnets` теперь поддерживает `create_ipam_network: true`; создаёт соответствующую `IPAMNetwork`, связанную с сервером и VNet, или возвращает существующую
- **Сетевые интерфейсы узлов** — полный CRUD для интерфейсов на уровне узла (мосты, связки, VLAN, ethernet): список, получение, создание, обновление, удаление через `proxmox_client.py`
- **Применение / Откат конфигурации сети узла** — `PUT` и `DELETE` на `/nodes/{node}/network` для активации или отката ожидающих изменений
- **API получения списка узлов** — `GET /api/servers/{server_id}/nodes` — возвращает узлы для сервера Proxmox (используется селекторами страницы сетей)

### 🧹 Очистка кода

- **Очистка импортов модуля SDN** — удалены неиспользуемые импорты (`ssl`, `asyncio`, `httpx`, `websockets`, `func`, `List` и т.д.) из `sdn.py`
- **Маршрутизатор сетей** — новый модуль `networks.py` под `api/proxmox/` с маршрутом HTML страницы и API для узлов; зарегистрирован в `proxmox/__init__.py`

### 🌍 i18n

- **49 новых ключей переводов** (EN + RU) для страницы сетей: типы интерфейсов, поля bridge/bond/VLAN, применение/откат конфигурации, метки интеграции IPAM, редактирование зоны/vnet, удаление подсети и многое другое

## [v1.3.0] - 2026-03-27

### 🖥️ Консоль — исправления VNC и терминала

- **VNC «Connection closed» исправлено** — `RFBClass` (noVNC) теперь получает строку URL WebSocket непосредственно вместо предварительно открытого объекта `WebSocket`; хак `onFirstMessage`, нарушавший квитирование RFB перед первым фреймом, полностью удалён из `virtual_machines.html` и `instance_detail.html`
- **VNCAuth исправлено для QEMU** — `vncproxy` теперь вызывается с `"generate-password": 1`; возвращаемый 8-символьный DES ключ передаётся в noVNC как пароль VNC; возвращается к `ticket` при отсутствии `password` (режим NoAuth Proxmox 9.x)
- **LXC `vncproxy` 500 исправлено** — LXC API `vncproxy` не принимает `generate-password`; параметр пропускается для LXC, который использует `ticket` как пароль VNC
- **Контекстное меню LXC открывает терминал xterm.js** — правый клик в списке ВМ теперь показывает **Терминал** для типа `lxc` (вызывает `openTerminalConsole()`) и **Консоль VNC** для типа `qemu`; ранее все типы использовали `openVNCConsole()`
- **Модальное окно терминала добавлено на страницу списка ВМ** — `#terminalModal` с полным xterm.js (FitAddon, WebLinksAddon, тема Dracula) добавлено в `virtual_machines.html`; переиспользует существующие API endpoints `GET /api/{server_id}/container/{vmid}/terminal` и `WebSocket /proxmox/ws/terminal/{server_id}/{node}/{vmid}`

## [v1.2.0] - 2026-03-16

### 🐛 Исправление ошибки — конфликт блокировки при изменении размера диска

- **Основная причина исправлена** — `resize.put()` в API Proxmox асинхронна и возвращает задачу UPID; старый код не ждал завершения этой задачи перед запуском ВМ, что заставляло Proxmox сообщать `can't lock file '/var/lock/qemu-server/lock-xxx.conf' — got timeout` и `command '/usr/bin/qemu-img resize' failed: got timeout`
- **`configure_vm` (создание ВМ из шаблона)** — теперь захватывает UPID изменения размера и вызывает `wait_for_task(120 s)` перед возвратом; ВМ может быть запущена только после полного изменения размера диска
- **`resize_vm_disk`** — то же исправление применено; задача изменения размера завершается перед возвратом функции
- **`resize_container_disk` (оба метода LXC)** — то же исправление; перезапуск контейнера выполняется только после подтверждения завершения задачи изменения размера
- **Удалено ненужное перезагрузка ВМ после изменения размера** — изменение размера диска QEMU происходит на уровне хранилища и не требует перезагрузки ВМ; автоматический вызов `restart_vm()` после ручного изменения размера удалён, чтобы предотвратить второй конфликт блокировки

## [v1.1.8] - 2026-03-16

### 👤 Назначение пользователю серверов

- **Таблица `user_servers`** (миграция 20) — новая таблица связей `User ↔ ProxmoxServer`; позволяет напрямую назначать конкретные серверы пользователям
- **API `GET /api/users/{id}/servers`** — список серверов, назначенных пользователю
- **API `GET /api/users/{id}/server-assignments`** — расширенный список всех серверов с флагами `assigned` и `compatible` (совместимость по рабочим областям)
- **API `PUT /api/users/{id}/servers`** — установка набора серверов для пользователя; проверяет пересечение рабочих областей — если сервер и пользователь не состоят ни в одной общей рабочей области, возвращает `409 workspace_conflict`
- **Фильтрация серверов для обычных пользователей** — пользователь видит только серверы, которые ему назначены **и** входят в его рабочую область

### 🖥️ Владелец ВМ / LXC

- **API `GET /api/{server_id}/vm/{vmid}/owner`** — получить текущего владельца ВМ/LXC и список доступных пользователей
- **API `PUT /api/{server_id}/vm/{vmid}/owner`** — назначить или снять владельца (только для админ); действие логируется в аудит

### 🔐 RBAC и роли

- **Миграция 21** — `dashboard:view` принудительно выставлен в `false` для роли `user` (новый формат ключей)
- **Миграция 22** — ключ `proxmox.cluster.manage` → `cluster:manage` в роли `admin`; старый dot-формат удаляется, чтобы не сбрасывать весь карту разрешений
- **`user_count`** в ответе `GET /api/roles` — для каждой роли возвращается количество активных пользователей

### 🚀 Умное перенаправление после входа

- После успешного входа производится запрос `GET /api/auth/me` — пользователь автоматически перенаправляется на первую страницу, к которой у него есть доступ (`/dashboard` → `/virtual-machines` → `/vms` → `/backups` → `/ipam` → `/logs` → `/settings`)
- Поддержка параметра `?returnUrl=` — возврат на запрошенную страницу после входа

### 🔧 Прочие улучшения

- `GET /api/servers` для непривилегированного пользователя объединяет фильтры `assigned_servers` и `WorkspaceServer` — пользователь видит только серверы из своей рабочей области, которые ему назначены
- `node_uptime` добавлен в ответ детального API сервера
